#What add-ons can doWas Add-ons können

An add-on is a normal Fabric or NeoForge mod that depends on Propwash and talks to it only through the package de.lardtom.propwash.api. It never changes Propwash itself, and built-in parts, saves and flight behaviour stay exactly as they are. Propwash: Just More Parts is built this way.

Ein Add-on ist ein normaler Fabric- oder NeoForge-Mod, der von Propwash abhängt und nur über das Paket de.lardtom.propwash.api mit ihm spricht. Propwash selbst ändert es nie; eingebaute Teile, Speicherstände und Flugverhalten bleiben genau, wie sie sind. Propwash: Just More Parts ist so gebaut.

#Rules for add-onsRegeln für Add-ons

These rules come from ADDONS.md in the Propwash source repository; the English text there is the binding one.

Diese Regeln stammen aus ADDONS.md im Propwash-Quellcode-Repository; maßgeblich ist der englische Text dort.

Everyone may build add-ons for Propwash. The add-on API, the example add-on and the documentation are MIT licensed, and your own code can use any license you like. To keep add-ons working side by side and with future Propwash releases, please follow these rules.

Jeder darf Add-ons für Propwash bauen. Die Add-on-API, das Beispiel-Add-on und die Dokumentation stehen unter der MIT-Lizenz, und dein eigener Code darf jede Lizenz haben, die du möchtest. Damit Add-ons nebeneinander und mit künftigen Propwash-Versionen funktionieren, halte dich bitte an diese Regeln.

#1. Use your own namespace – propwash is reserved.1. Nimm deinen eigenen Namensraum – propwash ist reserviert.

Use your mod id as the namespace for everything your add-on adds:

Nimm deine Mod-Id als Namensraum für alles, was dein Add-on hinzufügt:

  • registry ids: items, blocks, entities, parts, soundsRegistry-Ids: Items, Blöcke, Entities, Teile, Sounds
  • translation keys: <modid>.… and key.<modid>.…Übersetzungsschlüssel: <modid>.… und key.<modid>.…
  • key mappings and their categoryTastenbelegungen und ihre Kategorie
  • game rules and commandsSpielregeln und Befehle
  • network payloadsNetzwerk-Pakete
  • data and asset pathsDaten- und Asset-Pfade
  • NBT and data component keysSchlüssel für NBT und Data Components
  • config filesKonfigurationsdateien

The namespace propwash and the Java package de.lardtom.propwash belong to Propwash alone. Official add-ons use their own namespaces too, for example justmoreparts.

Der Namensraum propwash und das Java-Paket de.lardtom.propwash gehören allein Propwash. Auch offizielle Add-ons nutzen ihren eigenen Namensraum, zum Beispiel justmoreparts.

Why it matters:

Warum das wichtig ist:

  • Anything you put into propwash can collide with a future Propwash release without warning, and then your add-on or Propwash breaks.Alles, was du in propwash ablegst, kann ohne Vorwarnung mit einer künftigen Propwash-Version zusammenstoßen, und dann geht dein Add-on oder Propwash kaputt.
  • From Propwash 0.6.0, share codes identify every part by its namespace. A part registered under someone else's namespace breaks every code that contains it.Ab Propwash 0.6.0 erkennen Sharecodes jedes Teil an seinem Namensraum. Ein Teil, das unter einem fremden Namensraum angemeldet ist, macht jeden Code kaputt, in dem es steckt.

#2. Only the API is stable.2. Nur die API ist stabil.

  • Only de.lardtom.propwash.api is stable. It is versioned with API_VERSION (SemVer), and breaking changes come only with a major version.Stabil ist nur de.lardtom.propwash.api. Sie ist mit API_VERSION (SemVer) versioniert, und inkompatible Änderungen kommen nur mit einer neuen Hauptversion.
  • Everything else is internal and can change in any release, patch releases included.Alles andere ist intern und kann sich in jeder Version ändern, auch in Patch-Versionen.
  • Mixins into internal classes are allowed, but at your own risk. Crashes caused by add-ons are not supported. Please check whether a problem also happens without add-ons before you report it.Mixins in interne Klassen sind erlaubt, aber auf eigenes Risiko. Abstürze durch Add-ons werden nicht unterstützt. Prüf bitte, ob ein Problem auch ohne Add-ons auftritt, bevor du es meldest.

#3. Missing something? Ask for it.3. Fehlt dir etwas? Frag danach.

If the API lacks a hook you need, open an issue or ask on Discord instead of working around it with a mixin. Gaps get closed, for example custom switch functions, OSD elements and collision hooks.

Fehlt der API ein Haken, den du brauchst, öffne ein Issue oder frag im Discord, statt ihn mit einem Mixin zu umgehen. Lücken werden geschlossen, zum Beispiel eigene Schalterfunktionen, OSD-Elemente und Kollisions-Haken.

#Race data for servers and botsRenndaten für Server und Bots

Reading race results needs no mixin. From Propwash 0.6.0 every race course has a stable course id, and its leaderboards hang off that id. A mod reads courses and leaderboards through the read-only API de.lardtom.propwash.api.race (PropwashApi.race()) and listens to RaceEvents (laps, races, personal bests, course records, course changes). Without a mod, server scripts and bots read the same data as JSON files in the world folder under propwash/race-data/.

Zum Lesen von Rennergebnissen braucht es kein Mixin. Ab Propwash 0.6.0 hat jeder Rennkurs eine feste Kurs-Id, und an ihr hängen seine Bestenlisten. Eine Mod liest Kurse und Bestenlisten über die lesende API de.lardtom.propwash.api.race (PropwashApi.race()) und hört auf RaceEvents (Runden, Rennen, persönliche Bestzeiten, Kursrekorde, Kursänderungen). Ohne Mod lesen Server-Skripte und Bots dieselben Daten als JSON-Dateien im Weltordner unter propwash/race-data/.

#PartsBauteile

Every category has a definition record in api.part with a builder. Build definitions (…Definition, AirframeGeometry, FrameAero) only through their builders or with… methods; their constructors gain fields in minor versions. Small value records such as Vec3Mm, BatteryFitRule, PackSize or CellChemistry may be created with new. Every record checks its values and throws IllegalArgumentException naming the id.

Jede Kategorie hat einen Definitions-Record in api.part mit Builder. Definitionen (…Definition, AirframeGeometry, FrameAero) nur über Builder oder with…-Methoden bauen; ihre Konstruktoren bekommen in Nebenversionen neue Felder. Kleine Wertrecords wie Vec3Mm, BatteryFitRule, PackSize oder CellChemistry dürfen mit new entstehen. Jeder Record prüft seine Werte und wirft IllegalArgumentException mit der Id.

Coordinates are millimetres with the origin in the middle of the frame at the height of the stack plate: +X right, +Y up, −Z forward (the nose). Arms are always listed front left, front right, rear left, rear right.

Koordinaten sind Millimeter mit dem Ursprung in der Rahmenmitte auf Höhe der Stack-Auflage: +X rechts, +Y oben, −Z vorn (die Nase). Arme stehen immer in der Reihenfolge vorne links, vorne rechts, hinten links, hinten rechts.

#Accessory behaviour, inventory and actionsZubehör-Verhalten, Inventar und Aktionen

Players fill the inventory with the Accessories button in the drone’s service menu; the load stays with drone and item and adds weight in flight. Accessory action 1–4 are switch functions in the Modes tab and keys (numpad 9, 0, Enter and +; numpad 8 is turtle mode); every press and release is checked by the server (pilot, reset epoch, rate; a release only counts while the action is held) before onAction runs and ACCESSORY_ACTION fires. The Accessories window reads the drone’s current state before every access and writes back only the slots it changed itself, so writes through AccessoryInventory on the server and several open windows do not clash. It never takes shulker boxes (Item#canFitInsideContainerItems) or drone items with accessory contents of their own, even when accepts returns its default true.

#Impulses, pushes and forcesStöße, Schübe und Kräfte

PropwashApi.drones().physics(drone) gives impulse(J, framePoint) in N·s and push(F, frameRelative, framePoint, seconds) in N; Propwash sends them to the pilot’s flight model, the server return flight or a parked drone. Continuous forces (balloon, parachute) come from PropwashApi.flight().registerForces(id, profile -> provider) at 100 Hz on both sides. PropwashApi.drones() also finds drones near a point or a mob (with line of sight), aims with lead (aim) and scans for obstacles in six directions.

#Flight assistsFlughilfen

A FlightAssist runs at 100 Hz inside the pilot’s flight model and gets a FlightState (true and GPS/barometer-estimated position and velocity, attitude, sticks, accessory actions, obstacle distances). Through AssistOutput it sets sticks and mode, an altitude or climb rate, a position or velocity with a speed limit (Propwash’s ALTHOLD/POSHOLD loops with their sensor errors), a yaw rate or heading, an OSD label and may start GPS Rescue. Assists rest during GPS Rescue. While an add-on assist outputs anything (sticks, mode, altitude, position, velocity, yaw), the race lap counts as an assisted lap: reason other with the assist’s id as subject (characters [a-z0-9_:./-], at most 48). If it holds altitude or position without the pilot having switched a hold mode, only the assist is named, not “altitude hold was on”. Forces from registerForces do not count.

Eine FlightAssist läuft mit 100 Hz im Flugmodell des Piloten und bekommt einen FlightState (wahre und per GPS/Barometer geschätzte Position und Geschwindigkeit, Lage, Knüppel, Zubehör-Aktionen, Hindernisabstände). Über AssistOutput setzt sie Knüppel und Modus, eine Höhe oder Steigrate, eine Position oder Geschwindigkeit mit Tempogrenze (die Regelkreise von ALTHOLD/POSHOLD mit ihren Sensorfehlern), eine Gierrate oder einen Kurs, eine OSD-Anzeige und darf GPS Rescue starten. Während GPS Rescue ruhen Flughilfen. Solange eine Flughilfe eines Add-ons etwas ausgibt (Knüppel, Modus, Höhe, Position, Tempo, Gieren), zählt die Rennrunde als Runde mit Flughilfe: Grund other mit der Id der Flughilfe als Gegenstand (Zeichen [a-z0-9_:./-], höchstens 48). Hält sie Höhe oder Position, ohne dass der Pilot selbst Halten geschaltet hat, steht nur sie in der Wertung, nicht „Höhe halten war an“. Kräfte aus registerForces zählen nicht.

#What changes for mixin add-onsWas sich für Mixin-Add-ons ändert

Mixins into internals stay allowed, at your own risk; there is no compatibility layer. 0.6.0 changes among other things the switch mask (int → long in RadioFrame, SwitchEvaluator and their callers), generalises the server return flight to rescue.ServerFlight, changes the flight path in PilotSession and DroneSim (collision rules, surfaces, motor heat, freecam) and appends the OSD element FLIGHT_PATH_MARKER. #Race data for servers and botsRenndaten für Server und Bots

Servers and bots get their race data from Propwash itself: every course has a stable course id (a UUID) that its leaderboards hang off. A mod reads courses and leaderboards through PropwashApi.race() – read-only, on the server thread, as immutable snapshots – and listens to RaceEvents (lap, race, personal best, course record, course created, changed and deleted). Without a mod of your own, the same data lies as JSON in the world folder under propwash/race-data/ (courses.json, leaderboards/<course-id>.json). Times only come from real flying: there is no way to write into leaderboards.

Server und Bots bekommen ihre Renndaten von Propwash selbst: Jeder Kurs hat eine feste Kurs-Id (eine UUID), an der seine Bestenlisten hängen. Eine Mod liest Kurse und Bestenlisten über PropwashApi.race() – nur lesend, am Server-Thread, als unveränderliche Schnappschüsse – und hört auf RaceEvents (Runde, Rennen, persönliche Bestzeit, Kursrekord, Kurs angelegt, geändert, gelöscht). Ohne eigene Mod liegen dieselben Daten als JSON im Weltordner unter propwash/race-data/ (courses.json, leaderboards/<kurs-id>.json). Zeiten entstehen nur durch echtes Fliegen: In Bestenlisten schreiben lässt sich nichts.

Der Spieler sieht dann die Beitritts-Übersicht mit einer Karte je Add-on – welche Version er installieren, aktualisieren oder entfernen soll, und einen Link aus deinen Loader-Metadaten (siehe Name, Version und Homepage); das Server-Log nennt dieselben Unterschiede.
  • An add-on without parts that only one side has (for example a pure HUD add-on on the client) does not block joining; the overview lists it only as a note.Ein Add-on ohne Teile, das nur eine Seite hat (etwa ein reines HUD-Add-on beim Client), blockiert den Beitritt nicht; die Übersicht nennt es nur als Hinweis.
  • Add-on only on the player’s side (since 0.5.0): a player with your add-on may join a server without it. #Example add-onBeispiel-Add-on

The Propwash source code contains a complete example add-on in the namespace propwash_example (common/src/devtest/java/de/lardtom/propwash/dev/example/, MIT licensed) that uses only the API: version check, events, three parts in Java (2806.5 motor, 13″ carbon prop, stretched-X race frame with its own arms), five parts and a cell chemistry in JSON, items, a preset, its own creative tab, a workbench button with a child screen (preview, part check, import), a configurator tab (OSD layout via the clipboard, rates on the held drone) and a Flight School scene linked to its frames.

Der Propwash-Quellcode enthält ein vollständiges Beispiel-Add-on im Namensraum propwash_example (common/src/devtest/java/de/lardtom/propwash/dev/example/, MIT-lizenziert), das nur die API benutzt: Versionsprüfung, Events, drei Teile in Java (Motor 2806,5, 13″-Carbon-Prop, Stretched-X-Race-Rahmen mit eigenen Armen), fünf Teile und eine Zellchemie in JSON, Items, ein Preset, ein eigener Kreativ-Tab, ein Werkbank-Knopf mit Kind-Fenster (Vorschau, Teile-Check, Import), ein Konfigurator-Tab (OSD-Layout über die Zwischenablage, Rates auf die gehaltene Drohne) und eine Flugschul-Szene, die mit seinen Rahmen verknüpft ist.

Its deadcat frame as JSON is shown on the parts format page. Propwash: Just More Parts is the first real add-on built the same way.

Sein Deadcat-Rahmen als JSON steht auf der Seite zum Teile-Format. Propwash: Just More Parts ist das erste echte Add-on, das genauso gebaut ist.

#ChecklistCheckliste

  • requireVersion at start-up, dependency >=0.6.0- (Fabric) and [0.6.0-alpha,) (NeoForge) in the loader metadata, side = "BOTH".requireVersion beim Start, Abhängigkeit >=0.6.0- (Fabric) und [0.6.0-alpha,) (NeoForge) in den Loader-Metadaten, side = "BOTH".
  • Parts and items in the common init, client extensions in the client init.Teile und Items in der gemeinsamen Init, Client-Erweiterungen in der Client-Init.
  • Every id: path only [a-z0-9_.-], unique across all categories, in your own namespace – never propwash (rules for add-ons).Jede Id: Pfad nur [a-z0-9_.-], eindeutig über alle Kategorien, im eigenen Namensraum – nie propwash (Regeln für Add-ons).
  • A part table for share codes in your jar (Share codes), checked with ShareTableCheck.Eine Teile-Tabelle für Sharecodes im Jar (Sharecodes), geprüft mit ShareTableCheck.
  • An item icon assets/<ns>/items/<path>.json and a name part.<ns>.<path> for every part, in English and German.Ein Item-Symbol assets/<ns>/items/<pfad>.json und ein Name part.<ns>.<pfad> für jedes Teil, auf Englisch und Deutsch.
  • New mounts appear on at least one frame and one part (otherwise Propwash warns when the registry freezes).Neue Halterungen tauchen bei mindestens einem Rahmen und einem Teil auf (sonst warnt Propwash beim Einfrieren).
