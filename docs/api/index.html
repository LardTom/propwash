#What add-ons can doWas Add-ons können

An add-on is a normal Fabric or NeoForge mod that depends on Propwash and talks to it only through the package de.lardtom.propwash.api. It never changes Propwash itself, and built-in parts, saves and flight behaviour stay exactly as they are. Propwash: Just More Parts is built this way.

Ein Add-on ist ein normaler Fabric- oder NeoForge-Mod, der von Propwash abhängt und nur über das Paket de.lardtom.propwash.api mit ihm spricht. Propwash selbst ändert es nie; eingebaute Teile, Speicherstände und Flugverhalten bleiben genau, wie sie sind. Propwash: Just More Parts ist so gebaut.

Minecraft 26.3 is not obfuscated, so no remapping is involved. From the Modrinth Maven:

Propwash veröffentlicht drei Maven-Artefakte (Gruppe de.lardtom, je mit Quellen und Javadoc): propwash-common-26.3 mit der ganzen API in Mojang-Namen und die Loader-Jars propwash-fabric-26.3 und propwash-neoforge-26.3. Minecraft 26.3 ist nicht obfuskiert, es wird also nichts umbenannt. Über das Modrinth-Maven:

The variants carry the attribute io.github.mcgradleconventions.loader (common, fabric, neoforge) like the MultiLoader template, so an add-on built from that template picks the right one.

#Dependency in the loader metadataAbhängigkeit in den Loader-Metadaten

Propwash has to run on client and server, and so does the add-on: the part lists are compared when a player connects.

Propwash muss auf Client und Server laufen, das Add-on ebenso: Beim Verbinden werden die Teile-Listen verglichen.

#Checking the API versionAPI-Version prüfen

The API has its own version (PropwashApi.API_VERSION, SemVer), independent of the mod version: Propwash 0.5.1 ships 1.5.0. When your mod starts, require the major version and the smallest minor version whose features you need, and test for newer ones before using them:

Die API hat eine eigene Version (PropwashApi.API_VERSION, SemVer), unabhängig von der Mod-Version: Propwash 0.5.1 bringt 1.5.0. Beim Start die Hauptversion und die kleinste Nebenversion verlangen, deren Funktionen das Add-on braucht, und neuere vor dem Benutzen abfragen:

requireVersion throws an IllegalStateException with a clear message when Propwash is too old or has a different major version.

requireVersion wirft eine IllegalStateException mit klarer Meldung, wenn Propwash zu alt ist oder eine andere Hauptversion hat.

#PartsBauteile

Every category has a definition record in api.part with a builder. Build definitions (…Definition, AirframeGeometry, FrameAero) only through their builders or with… methods; their constructors gain fields in minor versions. Small value records such as Vec3Mm, BatteryFitRule, PackSize or CellChemistry may be created with new. Every record checks its values and throws IllegalArgumentException naming the id.

Jede Kategorie hat einen Definitions-Record in api.part mit Builder. Definitionen (…Definition, AirframeGeometry, FrameAero) nur über Builder oder with…-Methoden bauen; ihre Konstruktoren bekommen in Nebenversionen neue Felder. Kleine Wertrecords wie Vec3Mm, BatteryFitRule, PackSize oder CellChemistry dürfen mit new entstehen. Jeder Record prüft seine Werte und wirft IllegalArgumentException mit der Id.

Coordinates are millimetres with the origin in the middle of the frame at the height of the stack plate: +X right, +Y up, −Z forward (the nose). Arms are always listed front left, front right, rear left, rear right.

Koordinaten sind Millimeter mit dem Ursprung in der Rahmenmitte auf Höhe der Stack-Auflage: +X rechts, +Y oben, −Z vorn (die Nase). Arme stehen immer in der Reihenfolge vorne links, vorne rechts, hinten links, hinten rechts.

#In Java

  • Stator sizes come from the label (first two digits diameter, the rest height) or from statorSize(d, h). A new mount is just a new id; frames that fit name the same id in motorMount(…).Statormaße kommen aus der Bezeichnung (erste zwei Ziffern Durchmesser, Rest Höhe) oder aus statorSize(d, h). Eine neue Halterung ist einfach eine neue Id; passende Rahmen nennen dieselbe Id in motorMount(…).
  • Without arms, Propwash builds a true X from the wheelbase. With arms, mixer, lever arms, inertia, hull and hitbox follow from the geometry.Ohne arms rechnet Propwash einen True-X aus dem Radstand. Mit arms entstehen Mixer, Hebelarme, Trägheit, Hülle und Hitbox aus der Geometrie.
  • Every frame should set camera with a position: the lens usually sits 1–5 mm below the prop plane on X frames. Check the result with PropwashApi.builds().analyze(spec) (props in view) or cameraView(spec).Jeder Rahmen sollte camera mit Position setzen: Das Objektiv sitzt bei X-Rahmen meist 1–5 mm unter der Propebene. Prüfen mit PropwashApi.builds().analyze(spec) (Props im Bild) oder cameraView(spec).
  • Register cell chemistries (registerChemistry) before the batteries that use them.Zellchemien (registerChemistry) vor den Akkus anmelden, die sie benutzen.

#As JSONAls JSON

All fields, types and defaults are on the page Parts format (JSON). Tools can use Propwash’s own codec: parts().toJson(definition) and parts().fromJson(kind, id, json).

Dieselben Teile können Datendateien in den eigenen Ressourcen des Add-ons sein, data/<namensraum>/propwash_parts/<kategorie>/<pfad>.json, geladen mit PropwashApi.parts().loadBundled(modId). Alle Felder, Typen und Standards stehen auf der Seite Teile-Format (JSON). Werkzeuge können Propwashs eigenen Codec benutzen: parts().toJson(definition) und parts().fromJson(kind, id, json).

PropwashApi.builds() reads drone items (read), creates them (createDrone, withTune, withPaint), checks and analyses builds (check, analyze with the same figures as the workbench, cameraView, defaultTune) and runs imports on the server (applyImport). Battery charge, wear, bindings and switch assignments are never part of a DroneData.

PropwashApi.builds() liest Drohnen-Items (read), erzeugt sie (createDrone, withTune, withPaint), prüft und analysiert Baupläne (check, analyze mit denselben Werten wie die Werkbank, cameraView, defaultTune) und führt Importe auf dem Server aus (applyImport). Akkustand, Verschleiß, Bindungen und Schalterbelegung gehören nie zu einer DroneData.

#Import: the server decidesImport: Der Server entscheidet

The client sends a request; the server checks size and rate (at most two requests per second and player), the target, unknown parts and the game mode, applies the layers in the order parts → paint → tune → name and answers with an ImportResult. In survival, parts come from the inventory and paint costs dyes, as in the game.

Der Client schickt eine Anfrage; der Server prüft Größe und Rate (höchstens zwei Anfragen pro Sekunde und Spieler), das Ziel, unbekannte Teile und den Spielmodus, wendet die Ebenen in der Reihenfolge Teile → Lack → Tuning → Name an und antwortet mit einem ImportResult. Im Überlebensmodus kommen Teile aus dem Inventar und Lack kostet Farbstoffe, wie im Spiel.

Statuses: APPLIED, UNCHANGED, UNKNOWN_PARTS, MISSING_PARTS, MISSING_DYES, NO_TARGET, NOT_ALLOWED, INVALID, BUSY; show them with Component.translatable(result.status().translationKey()).

Status: APPLIED, UNCHANGED, UNKNOWN_PARTS, MISSING_PARTS, MISSING_DYES, NO_TARGET, NOT_ALLOWED, INVALID, BUSY; anzeigen mit Component.translatable(result.status().translationKey()).

Share codes live in the add-on: Propwash provides the data, the check and the server-checked import. Never put the video channel (TuneGroup.VTX), switch assignments, battery charge or bindings into a code.

Sharecodes leben im Add-on: Propwash liefert Daten, Prüfung und den vom Server geprüften Import. Nie den Videokanal (TuneGroup.VTX), Schalterbelegung, Akkustand oder Bindungen in einen Code schreiben.

#Workbench buttonsWerkbank-Knöpfe

init runs every time the workbench screen is built. Up to two buttons sit left of Paint, more go behind “⋯”; headerSpace(), short labels and 13 × 13 px icon buttons help with long texts. WorkbenchContext gives the slots, the finished drone (result()), missingParts(data) and the import into the workbench.

init läuft bei jedem Aufbau des Werkbank-Screens. Bis zu zwei Knöpfe stehen links neben Lackierung, weitere hinter „⋯“; headerSpace(), Kurzbeschriftungen und Symbol-Knöpfe mit 13 × 13 px helfen bei langen Texten. WorkbenchContext liefert die Slots, die fertige Drohne (result()), missingParts(data) und den Import in die Werkbank.

#Configurator tabsKonfigurator-Tabs

PropwashClientApi.registerConfigTab(ShareCodeTab::new). A tab extends ui.client.config.ConfigTab: an id with namespace, its own order() from 1000, widgets in build(), drawing in extract(…), save() and discard(). openConfigTab(id, parent) opens the configurator right on it.

PropwashClientApi.registerConfigTab(ShareCodeTab::new). Ein Tab erweitert ui.client.config.ConfigTab: Id mit Namensraum, eigene order() ab 1000, Widgets in build(), Zeichnen in extract(…), save() und discard(). openConfigTab(id, parent) öffnet den Konfigurator direkt darauf.

#Flight School scenesFlugschul-Szenen

Add-on scenes need an id in the add-on’s namespace and use the scene builder in guide.scene. Holding the Flight School key over an item opens its scenes; add-on batteries, video units, stacks and props get the matching Propwash scene automatically.

Add-on-Szenen brauchen eine Id im Namensraum des Add-ons und benutzen den Szenen-Baukasten in guide.scene. Die Flugschul-Taste über einem Item öffnet seine Szenen; Akkus, Videomodule, Stacks und Props von Add-ons bekommen die passende Propwash-Szene von selbst.

#Theme

Every screen that hooks into Propwash uses the Propwash theme: ThemedScreen, ThemeDraw, ThemeText, Palette, Metrics, FlatButton, ScrollPanel, StepSlider and TextField. These classes are released for add-ons and only ever get additions.

Jedes Fenster, das sich in Propwash einklinkt, benutzt das Propwash-Theme: ThemedScreen, ThemeDraw, ThemeText, Palette, Metrics, FlatButton, ScrollPanel, StepSlider und TextField. Diese Klassen sind für Add-ons freigegeben und werden nur ergänzt.

#Stability and versionsStabilität und Versionen

  • SemVer: the major version changes with every incompatible change, the minor version with additions, the patch version with fixes.SemVer: Die Hauptversion steigt bei jeder inkompatiblen Änderung, die Nebenversion bei Ergänzungen, der Patch bei Fehlerbehebungen.
  • Stable: api.* plus the released internal types ConfigTab, ConfigTabHost, StepSlider, Palette, Metrics, ThemeText, ThemeDraw, ThemedWidgets, ThemedScreen, FlatButton, ScrollPanel, TextField and guide.scene.*. Everything else is internal and may change in any version.Stabil: api.* und die freigegebenen internen Typen ConfigTab, ConfigTabHost, StepSlider, Palette, Metrics, ThemeText, ThemeDraw, ThemedWidgets, ThemedScreen, FlatButton, ScrollPanel, TextField und guide.scene.*. Alles andere ist intern und darf sich in jeder Version ändern.
  • Records: definitions only through builders; value records keep their canonical constructor (a new component comes with an extra constructor).Records: Definitionen nur über Builder; Wertrecords behalten ihren kanonischen Konstruktor (eine neue Komponente kommt mit einem zusätzlichen Konstruktor).
  • Enums get new constants at the end in minor versions, so always switch with a default. #MultiplayerMehrspieler

  • When a player connects, Propwash compares the Propwash version, the network protocol, the add-on list and the part lists of server and client (ids and a short hash per definition). If the server has parts the player lacks (or a different version of them), or the protocol differs, the player cannot join: the flight model runs on the client and has to see the same data. The player then sees the join overview with one card per add-on – which version to install, update or remove, and a link from your loader metadata (see Name, version and homepage); the server log lists the same differences.Beim Verbinden vergleicht Propwash Version, Netzprotokoll, Add-on-Liste und Teile-Listen von Server und Client (Ids und ein kurzer Hash je Definition). Fehlen dem Spieler Teile des Servers (oder hat er sie in anderer Version) oder weicht das Protokoll ab, kann der Spieler nicht beitreten: Das Flugmodell läuft auf dem Client und muss dieselben Daten sehen. Der Spieler sieht dann die Beitritts-Übersicht mit einer Karte je Add-on – welche Version er installieren, aktualisieren oder entfernen soll, und einen Link aus deinen Loader-Metadaten (siehe Name, Version und Homepage); das Server-Log nennt dieselben Unterschiede.
  • An add-on without parts that only one side has (for example a pure HUD add-on on the client) does not block joining; the overview lists it only as a note.Ein Add-on ohne Teile, das nur eine Seite hat (etwa ein reines HUD-Add-on beim Client), blockiert den Beitritt nicht; die Übersicht nennt es nur als Hinweis.
  • Add-on only on the player’s side (since 0.5.0): a player with your add-on may join a server without it. Propwash switches the add-on off for that session and shows “Add-on inactive on this server”: its parts and cell chemistries, part items, creative tab, presets, workbench extensions, configurator tabs and Flight School scenes are hidden, and imports with its parts are not sent. Ask for the state with PropwashClientApi.isAddonActive("<modid>") (API 1.5). For this to work: create every id (parts, items, presets, workbench extensions, tabs <modid>:…, scenes <modid>:…) in the namespace of your mod id; register your own items, blocks or entities only if you must and hide directly registered items while the add-on is inactive; register network channels as optional (NeoForge: event.registrar("1").optional()) and check before sending (connection.hasChannel(…), Fabric ClientPlayNetworking.canSend(…)); never send anything about your parts yourself – use sendImport/sendCreateDrone. Server-side features (commands, loot, recipes, server events) only run where the add-on is installed anyway.Add-on nur beim Spieler (seit 0.5.0): Ein Spieler mit deinem Add-on darf einem Server ohne es beitreten. Propwash schaltet das Add-on für diese Sitzung ab und zeigt „Add-on auf diesem Server inaktiv“: Seine Teile und Zellchemien, Teil-Items, Kreativ-Tab, Presets, Werkbank-Erweiterungen, Konfigurator-Tabs und Flugschul-Szenen sind ausgeblendet, Importe mit seinen Teilen werden nicht gesendet. Den Zustand fragst du mit PropwashClientApi.isAddonActive("<modid>") ab (API 1.5). Damit das klappt: Lege jede Id (Teile, Items, Presets, Werkbank-Erweiterungen, Tabs <modid>:…, Szenen <modid>:…) im Namensraum deiner Mod-Id an; registriere eigene Items, Blöcke oder Entities nur, wenn es sein muss, und blende direkt registrierte Items aus, solange das Add-on inaktiv ist; melde Netzwerk-Kanäle optional an (NeoForge: event.registrar("1").optional()) und prüfe vor dem Senden (connection.hasChannel(…), Fabric ClientPlayNetworking.canSend(…)); sende nie selbst etwas über deine Teile – nimm sendImport/sendCreateDrone. Server-Funktionen (Befehle, Beute, Rezepte, Server-Events) laufen ohnehin nur dort, wo das Add-on installiert ist.
  • If an add-on is removed from a world, drones with its parts survive: Propwash keeps the unknown id in a placeholder part (not armable, tooltip “Unknown part”). When the add-on comes back, the drone is complete again.Wird ein Add-on aus einer Welt entfernt, bleiben Drohnen mit seinen Teilen erhalten: Propwash behält die unbekannte Id in einem Platzhalter (nicht scharfschaltbar, Tooltip „Unbekanntes Bauteil“). Kommt das Add-on zurück, ist die Drohne wieder vollständig.

#Example add-onBeispiel-Add-on
